Wie HAULITZ Ihr Unternehmen schützt

Vier deterministische Schutzschranken im Code, bevor Finanzdaten in unveränderbare Ledger fließen.

Spart bis zu 12.000 € Rundungsverluste pro 10.000 Belege

Positionsrundung & Cent-Genauigkeit

Kumulierte Rundungsdifferenzen über Dutzende Rechnungspositionen oder Währungsumrechnungen bringen ERP-Abstimmungen zum Stillstand. HAULITZ rechnet strikt in 64-Bit Integer-Cents (BigInt) und verhindert Rundungsdrift vor dem Hauptbuch.

Gleitkomma-Drift
50 × €0,3781 → 50 × €0,38 = €19,00 (Delta +€0,09)
❌ Kumulierte Rundungsabweichung
vs
HAULITZ 64-Bit Cent-Genauigkeit
50 × 199¢ @ 19% = 1890,5¢ → 1891¢ (€18,91)
✔ Exakter Cent-Abgleich nach Gesetz
TESTWERTE AUSWÄHLEN:
Verhindert Fehlüberweisungen & Bank-Rücklastgebühren

ISO 7064 MOD 97-10 Prüfziffern

Validiert IBAN-Syntax und Prüfziffern mathematisch per ISO 7064 MOD 97-10 vor dem Anstoßen von SEPA-Überweisungen. Fängt Tippfehler und Zahlendreher zuverlässig ab. (Hinweis: Prüft Syntaxintegrität; Kontoverifikation erfordert Bankverzeichnisabfrage).

Modulo-97 Rest == 1 Gültig (ISO 7064 MOD 97-10)
Schützt SAP S/4HANA vor Stammdaten- und Schemakorruption

Pre-Staging ERP-Firewall

Dient als automatisierter Prüfpuffer vor SAP S/4HANA (BAPI_INCOMINGINVOICE_CREATE / INVOIC02) und DATEV. Fehlerhafte Belege erzeugen strukturierte Beanstandungsmemos vor dem Staging.

Eingang (ZUGFeRD / XRechnung)
Gültig → SAP S/4HANA Staging
Ungültig → Auto-Mängelrüge
Erfüllt BMF-Grundsätze zur Unveränderbarkeit (GoBD § 147 AO)

Revisionssicherer SHA-256 Prüfpfad

Jeder Prüflauf wird kryptografisch mit dem Vorgängerblock verkettet und unterstützt GoBD-Anforderungen an Unveränderbarkeit und Prüfbarkeit (gemäß BMF-Schreiben). Zielarchitektur für PostgreSQL in Frankfurt (AWS eu-central-1).

// ============================================================================
// HAULITZ CLIENT SDK - PRODUCTION C# / .NET 8 INTEGRATION DRIVER

// Package: Microsoft.Data.SqlClient 5.2+ | System.Text.Json

using System;
using System.Data;
using System.Text.Json;
using System.Threading.Tasks;
using Microsoft.Data.SqlClient;

namespace Haulitz.Enterprise.Integration
{
    public sealed class HaulitzIngestionService
    {
        private readonly string _connectionString;

        public HaulitzIngestionService(string connectionString)
        {
            _connectionString = connectionString ?? throw new ArgumentNullException(nameof(connectionString));
        }

        public async Task<Guid> StageVerifiedRecordAsync(
            string referenceNumber,
            string domainSector,
            bool isClean,
            decimal varianceAmount,
            string gobdSeal,
            string previousSeal,
            object payload,
            object auditLog)
        {
            const string sql = @"
                INSERT INTO [dbo].[Staging_FINTECH_Ingest] (
                    [ReferenceNumber], [DomainSector], [AuditStatus], [AtlasReady], 
                    [QuarantineHold], [VarianceAmount], [PayloadHash], [GoBDSeal], 
                    [PreviousSeal], [RawPayloadJSON], [VerificationLog]
                ) 
                OUTPUT INSERTED.[IngestID]
                VALUES (
                    @ReferenceNumber, @DomainSector, @AuditStatus, @AtlasReady, 
                    @QuarantineHold, @VarianceAmount, @PayloadHash, @GoBDSeal, 
                    @PreviousSeal, @RawPayloadJSON, @VerificationLog
                );";

            await using var connection = new SqlConnection(_connectionString);
            await connection.OpenAsync();

            await using var command = new SqlCommand(sql, connection);
            command.Parameters.Add("@ReferenceNumber", SqlDbType.NVarChar, 100).Value = referenceNumber;
            command.Parameters.Add("@DomainSector", SqlDbType.NVarChar, 50).Value = domainSector;
            command.Parameters.Add("@AuditStatus", SqlDbType.NVarChar, 30).Value = isClean ? "VERIFIED_CLEAN" : "QUARANTINE_HOLD";
            command.Parameters.Add("@AtlasReady", SqlDbType.Bit).Value = isClean;
            command.Parameters.Add("@QuarantineHold", SqlDbType.Bit).Value = !isClean;
            var paramVariance = command.Parameters.Add("@VarianceAmount", SqlDbType.Decimal);
            paramVariance.Precision = 18;
            paramVariance.Scale = 2;
            paramVariance.Value = varianceAmount;
            command.Parameters.Add("@PayloadHash", SqlDbType.Char, 64).Value = gobdSeal;
            command.Parameters.Add("@GoBDSeal", SqlDbType.Char, 64).Value = gobdSeal;
            command.Parameters.Add("@PreviousSeal", SqlDbType.Char, 64).Value = previousSeal;
            command.Parameters.Add("@RawPayloadJSON", SqlDbType.NVarChar, -1).Value = JsonSerializer.Serialize(payload);
            command.Parameters.Add("@VerificationLog", SqlDbType.NVarChar, -1).Value = JsonSerializer.Serialize(auditLog);

            var result = await command.ExecuteScalarAsync();
            return (Guid)result!;
        }
    }
}

Architektur- & Integrationsfragen für Lead Architects

Präzise Antworten zu SAP S/4HANA Staging, GoBD-Grundsätzen, cent-genauer Mathematik und DSGVO-Architektur.

HAULITZ fungiert als deterministischer Vor-Staging-Puffer. Eingehende Rechnungen werden vor dem Schreiben in Produktivtabellen validiert. Konforme Belege werden als strukturierte Parameter-Objekte für SAP BAPIs (BAPI_INCOMINGINVOICE_CREATE), IDocs (INVOIC02) oder DATEV-Staging-Tabellen aufbereitet. Fehlerhafte Belege generieren automatisierte Beanstandungsmemos ohne Schema-Mutationen.

Nein. In dieser Referenzarchitektur erfolgt die mathematische Validierung flüchtig im Speicher. Für eine GoBD-konforme Prüfpfaddokumentation werden lediglich kryptografische SHA-256 Hashes und Metadaten festgeschrieben. Vertrauliche Originalbelege verbleiben in der geschützten Kundeninfrastruktur.

HAULITZ berechnet alle Posten und USt-Stufen (§ 12 Abs. 1 für 19%, § 12 Abs. 2 für 7% gem. UStG) strikt centgenau über 64-Bit Integer-Arithmetik (BigInt). Kumulierte Rundungsfehler zwischen Zeilenrundung und Summenrundung werden vor der Verbuchung abgeglichen.

Unterstützt werden ZUGFeRD 2.2, Factur-X, nationale XRechnung (CII- und UBL-Syntax) sowie strukturierte EDIFACT-Nachrichten. Unstrukturierte PDF-Rechnungen können über vorgelagerte OCR-Gateways eingespeist werden.

Das Frontend dieser Referenzarchitektur wird über Cloudflare Edge ausgeliefert. Die Produktiv-Zielarchitektur ist für private VPC-Deployments in Frankfurt am Main (AWS eu-central-1 / deutsche Rechenzentren) ausgelegt, um volle DSGVO-Datenhoheit und GoBD-Revisionssicherheit zu gewährleisten.
